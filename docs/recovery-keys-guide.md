# Инструкция: где взять 7 недостающих ключей FunnelHub

Все значения вписывать **только** в `projects/funnel-hub/.env.recovery.template`.
Файл под `.gitignore`, в чат и в git значения не попадают.

> **Про названия кнопок.** Пути в интерфейсах VK, VK ID и Яндекс Облака меняются
> чаще, чем документация. Ниже указаны актуальные на момент написания названия
> разделов; если кнопка называется иначе — ориентируйтесь на смысл (ключи,
> Callback API, Redirect URI). Технические значения (пути эндпоинтов, формат
> ключей, переменные) сверены с кодом проекта и не приблизительны.

Порядок важен: пункты 1–4 закрываются сразу, пункт 5 требует, чтобы
`bot.aisukam.ru` уже указывал на новый сервер и отвечал по HTTPS.

| # | Ключ | Где взять | Нужен домен? |
|---|------|-----------|--------------|
| 1 | `AISU_SMARTCAPTCHA_SERVER_KEY` | Яндекс Облако → SmartCaptcha | нет |
| 2 | `VK_OAUTH_CLIENT_ID`, `VK_OAUTH_CLIENT_SECRET` | VK ID (id.vk.com) | нет (проверка — да) |
| 3 | `MOST_VK_GROUP_ID`, `MOST_VK_GROUP_SCREEN_NAME` | Панель сообщества VK | нет |
| 4 | `MOST_VK_GROUP_ACCESS_TOKEN` | Панель сообщества VK → Работа с API | нет |
| 5 | `MOST_VK_CONFIRMATION_CODE` | Панель сообщества VK → Callback API | **да** |

---

## 1. `AISU_SMARTCAPTCHA_SERVER_KEY` — Яндекс Облако

Это самый срочный ключ: без него формы сайта уходят в fallback и заявки
не попадают в FunnelHub.

1. Открыть <https://console.yandex.cloud> и войти тем же аккаунтом Яндекса,
   под которым создавалась капча.
2. Выбрать каталог (folder) — капча привязана к каталогу, не к аккаунту целиком.
3. В левом меню: **SmartCaptcha** (раздел «Безопасность»).
4. В списке найти капчу, у которой **клиентский ключ** начинается на
   `ysc1_lk4O3WN`. Это значение уже лежит локально в
   `projects/main-site/lead-config.php` (`AISU_SMARTCAPTCHA_SITEKEY`) —
   сравнить полностью.
5. Открыть эту капчу → вкладка/блок **«Ключи»** (или «Обзор»).
6. Скопировать **серверный ключ**. Важно не перепутать:
   - **клиентский** (sitekey) начинается на `ysc1_` — он уже есть локально;
   - **серверный** (secret) начинается на `ysc2_` — нужен нам.

   Ключи различаются префиксом, поэтому перепутать сложно, но если вписать
   `ysc1_…`, сервер вернёт `403` на каждой заявке.

Вписать:

```
AISU_SMARTCAPTCHA_SERVER_KEY=<серверный ключ>
```

Проверка (после подъёма бэкенда). Важно: эндпоинт сначала проверяет
Bearer-токен и только потом капчу, поэтому тестовый запрос должен содержать
настоящий `AISU_LANDING_INGEST_TOKEN`:

```
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://bot.aisukam.ru/webhooks/landing-applications/aisu \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <AISU_LANDING_INGEST_TOKEN>" \
  -d '{"name":"probe","smartcaptcha_token":"000000000000000000000000"}'
```

Как читать код ответа:

| Ответ | Значение |
|---|---|
| `403` | **Ключ работает.** Капча вызвана, токен-заглушка отклонена — это и есть успех проверки |
| `503` | Ключ не задан или Яндекс недоступен — `SmartCaptcha server key is not configured` |
| `401` | Неверный Bearer-токен, капча вообще не проверялась |
| `422` | Не хватает полей в теле запроса, до капчи не дошло |

Если капчи в консоли нет — проверить другой аккаунт Яндекса. Ключ можно
пересоздать: «Создать капчу» → тип **SmartCaptcha** → после создания
клиентский ключ заменить в `lead-config.php` на сайте (иначе старые формы
перестанут проходить проверку).

## 2. `VK_OAUTH_CLIENT_ID` и `VK_OAUTH_CLIENT_SECRET` — VK ID

Код проекта использует **VK ID** (`https://id.vk.ru/authorize`), а не старый
`oauth.vk.com`. Значит приложение должно быть создано в VK ID.

1. Открыть <https://id.vk.com/about/business/go> → войти под аккаунтом
   владельца сообщества.
2. Раздел **«Мои приложения»** → **«Создать приложение»** (если приложения нет).
3. Тип: **Веб-приложение**. Название: `FunnelHub` или `Школа Айсу Кам`.
4. В настройках приложения указать **Redirect URI**:

   ```
   https://bot.aisukam.ru/oauth/vk/callback
   ```

   Это ровно то, что строит код: `{PUBLIC_BASE_URL}/oauth/vk/callback`
   (см. `src/funnelhub/services/vk_oauth.py`, функция `build_vk_oauth_redirect_uri`).
   Схема, домен и путь должны совпадать символ в символ, иначе VK вернёт ошибку.
5. Скопировать **ID приложения** → это `VK_OAUTH_CLIENT_ID` (число).
6. Скопировать **Защищённый ключ** (Client Secret) → `VK_OAUTH_CLIENT_SECRET`.

Вписать:

```
VK_OAUTH_CLIENT_ID=<число>
VK_OAUTH_CLIENT_SECRET=<защищённый ключ>
```

`VK_OAUTH_STATE_SECRET` уже сгенерирован, трогать не нужно.

Проверка: после подъёма сервера открыть ссылку вида
`https://bot.aisukam.ru/join/<токен>/vk` — должна открыться страница
авторизации VK ID, а не ошибка.

> Если приложение уже существовало ранее: старый Client Secret восстановить
> нельзя, только **«Перевыпустить»** (кнопка рядом с ключом). Redirect URI
> при этом нужно вписать заново — при взломе Beget старый домен мог остаться.

## 3. `MOST_VK_GROUP_ID` и `MOST_VK_GROUP_SCREEN_NAME` — сообщество «Мост ценностей»

1. Открыть <https://vk.com/groups> под аккаунтом, который **админ** этого
   сообщества (не просто участник).
2. Найти сообщество «Мост ценностей» → открыть его.
3. В правом меню **«Управление»** → вкладка **«Настройки»** → блок
   **«Адрес»**.
4. `MOST_VK_GROUP_SCREEN_NAME` — короткий адрес без `vk.com/`
   (например `most_cennostei`).
5. `MOST_VK_GROUP_ID` — числовой ID. Он есть в адресной строке страницы
   управления: `vk.com/club123456789` → `123456789`. Либо в блоке
   «Настройки» → «Основная информация» → «ID сообщества».

Вписать:

```
MOST_VK_GROUP_ID=<число>
MOST_VK_GROUP_SCREEN_NAME=<короткий адрес>
```

> Не путать с `VK_GROUP_ID=211582267` — это **основное** сообщество школы.
> У «Моста» ID другой.

## 4. `MOST_VK_GROUP_ACCESS_TOKEN` — ключ доступа сообщества

1. В том же сообществе: **«Управление»** → вкладка **«Работа с API»**.
2. Если нет приложения — **«Создать ключ»**.
3. Права: поставить галочки
   **«Управление сообществом»**, **«Сообщения сообщества»**, **«Фотографии»**,
   **«Стена»** (код отправляет сообщения, фото и посты).
4. Подтвердить → скопировать ключ (длинная строка ~200+ символов).
5. Проверить, что ключ не «тестовый» — у тестового ограниченный набор методов.

Вписать:

```
MOST_VK_GROUP_ACCESS_TOKEN=<ключ>
```

Проверка — сразу после получения, не дожидаясь сервера:

```
curl -s "https://api.vk.com/method/groups.getById?group_id=<MOST_VK_GROUP_ID>&access_token=<ключ>&v=5.199"
```

Успех — `{"response":[...]}`, где есть нужное сообщество.
Ошибка `5` или `1116` — ключ неверный, перевыпустить.

## 5. `MOST_VK_CONFIRMATION_CODE` — только после переключения DNS

**Важно:** эту строку нельзя придумать. Её выдаёт VK, и получить её можно
только когда URL уже отвечает по HTTPS. Поэтому пункт идёт последним.

Порядок строго такой:

1. Убедиться, что сервер поднят и `https://bot.aisukam.ru/health` отвечает.
2. В сообществе: **«Управление»** → **«Работа с API»** → **«Callback API»**.
3. Вкладка **«Настройки сервера»**:
   - **Адрес**: `https://bot.aisukam.ru/webhooks/most-vk`
     (для основного сообщества — `https://bot.aisukam.ru/webhooks/vk`)
   - **Секретный ключ**: значение `MOST_VK_CALLBACK_SECRET` из шаблона
     (уже сгенерировано, 32 символа). Скопировать из файла и вставить в VK.
4. VK покажет строку **«Строка, которую должен вернуть сервер»** —
   это и есть `MOST_VK_CONFIRMATION_CODE`. Скопировать.
5. Вписать в шаблон:

```
MOST_VK_CONFIRMATION_CODE=<строка из VK>
```

6. Перезапустить контейнеры, затем в VK нажать **«Подтвердить»**.
   VK отправит запрос `type=confirmation`, сервер вернёт эту строку,
   статус станет «Callback API подключён».
7. В блоке «Типы событий» включить: **«Входящее сообщение»**,
   **«Разрешение на сообщения»**.

Проверка вручную, до нажатия «Подтвердить»:

```
curl -s -X POST https://bot.aisukam.ru/webhooks/most-vk -H "Content-Type: application/json" -d '{"type":"confirmation","group_id":<MOST_VK_GROUP_ID>,"secret":"<MOST_VK_CALLBACK_SECRET>"}'
```

Ожидается — ровно та строка, что в `MOST_VK_CONFIRMATION_CODE`.

## 6. Рекомендуется: ротация Telegram-токенов

Все три бота сейчас **живы** и работают со старыми токенами:

| Переменная | Бот | ID |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | @vedicschool_aisu_bot | 8963890043 |
| `MOST_TELEGRAM_BOT_TOKEN` | @most_cannostei_bot | 8705381132 |
| `INBOX_NOTIFY_TELEGRAM_BOT_TOKEN` | @leadsaisubot | 8978645229 |

Токены лежали на взломанном хосте. Ротация:

1. Открыть <https://t.me/BotFather> → `/mybots`.
2. Выбрать бота → **API Token** → **Revoke current token**.
3. Скопировать новый токен в соответствующую переменную.
4. Для каждого проверить:

```
curl -s "https://api.telegram.org/bot<токен>/getMe"
```

Ожидается `"ok":true` и правильный `username`.

Побочный эффект: старый токен мгновенно перестаёт работать — если бот ещё
крутится на Beget, он упадёт в ошибку авторизации. Это нормально, Beget мы
выводим из эксплуатации.
